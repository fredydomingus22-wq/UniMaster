UniMaster: multi-community learning SaaS

Blueprint for a production-ready platform that empowers garimpeiros to run communities, monetize courses, and deliver content securely to students.

Server-first

RSC by default, server actions for mutations, client components only when UX needs interactivity.

Architecture snapshot

Composable Next.js 14 app router with Supabase as the single backend surface.

Frontend

  • App Router, nested layouts, route groups for public vs. private areas.
  • Atomic design system with TailwindCSS + shadcn/ui atoms & molecules.
  • Server Components for data reads; client wrappers for forms and media players.
  • Zod + React Hook Form for validation and type-safe server actions.

Backend / Data

  • Supabase Postgres with RLS enforcing community_id isolation.
  • Supabase Auth JWT for both server actions and client session recovery.
  • Storage buckets for video/pdf uploads; UploadThing optional.
  • Triggers for ordering and consistency (course & lesson indices).

Domain model

Single-owner communities with multi-tenant isolation and student subscriptions.

Users

Roles: admin, garimpeiro (owner), student.

  • Fields: id, name, email, role, university, avatar_url, created_at.
  • Has many communities (owner), posts, comments, subscriptions.

Communities

One garimpeiro → many students.

  • Fields: id, owner_id, name, description, banner_url, price_monthly, visibility, created_at.
  • Has many courses, posts, events.

Courses & lessons

Ordered collections for premium learning paths.

  • Course fields: id, community_id, title, description, order_index, created_at.
  • Lesson fields: id, course_id, title, video_url, pdf_url, order_index, created_at.

Posts & comments

Community feed similar to Skool with threaded comments.

  • Post belongs to user & community; comment belongs to post & user.
  • Policies restrict visibility to subscribers of the community.

Subscriptions

Controls student access and billing reconciliation.

  • Fields: id, user_id, community_id, status, started_at, expires_at.
  • Only active subscriptions grant course and feed access.

Events

Live sessions (Zoom/Meet) surfaced in calendars.

  • Fields: id, community_id, title, start_time, end_time, link, visibility.
  • RLS mirrors course access: subscribers only.

Feature flow

Each feature aligns UI, API, DB, and validation steps.

Community creation

Server action creates community row with owner_id; RLS ensures only owner can mutate. Banner stored in Supabase Storage.

Course & lesson authoring

Server actions validate with Zod, write course/lesson records, trigger maintains order_index.

Content delivery

Server components stream course/lesson data; client player handles video with signed URLs from Supabase Storage.

Subscriptions

Stripe/webhook updates subscription status; RLS gate keeps course, posts, and events per community_id.

Deployment checklist

Production posture for Vercel + Supabase.

Frontend readiness

  • Environment variables mapped via env.local and Vercel dashboard.
  • Edge runtime only where cacheable; node runtime for server actions using Supabase client.
  • Static assets optimized; fonts loaded via next/font.

Security & RLS

  • Policies isolate rows by community_id and enforce ownership for writes.
  • JWT claims include role and community_id for multi-tenant awareness.
  • Storage policies restrict uploads to owners; signed URLs for consumption.
